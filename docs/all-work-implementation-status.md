## 원래 제안 6개에 대한 정확한 상태

1. **기억의 단위 — 부분 완료.** 9개 카드에 기존 상세의 문제·리서치·설계 섹션을 연결했다. 하지만 실제 문제 메모·프로토타입·출시 화면 이미지로 교체하지는 않았다.
2. **관련성 — 구현.** 호버한 카드와 같은 프로젝트의 fragment에만 미세한 밝기 차이를 준다.
3. **선택한 것이 전경으로 — 구현.** 탐색은 연속 흐름이며 상세를 여는 경우에만 펼친다. 터치의 이름/버튼 위치는 고정이다. PC는 요청한 K95 방식의 커서 인접 라벨이다.
4. **상세는 생각의 확대본 — 부분 완료.** 관련 섹션 이동과 오버레이 복귀 위치 보존은 구현. 실제 동일 이미지를 상세 히어로와 연결한 전환은 아직 아니다.
5. **고정 기준점 — 구현.** 아이보리 배경, 녹색 UI, 일관된 번호와 이름. 긴 설명은 추가하지 않았다.
6. **짧은 한 문장 — 구현.** 메인 링크의 Inside my work만 추가했다.

## 아직 안 된 것 — 우선순위

### P0 · 실제 콘텐츠와 근거

- 현재 커버는 설명용 SVG 6장과 스톡 사진 3장이다. 갤러리 사진은 실제 SeMA 현장 사진이 아니다. [에셋 출처](work-gallery-assets.md).
- 프로젝트별 실제 리서치 메모, 설계 대안, 작동 프로토타입, 출시/검증 자료를 받아 fragment 이미지로 대체해야 한다. 기존 상세의 연구·성과 문구도 이번 작업에서 사실 검증한 것은 아니다.
- 지금의 변화는 **배치의 반복감을 줄이는 것**이다. 원본 콘텐츠가 9장인 이상 의미와 이미지의 반복 자체는 남는다. 새 이미지를 임의 생성해 실제 프로젝트 증거인 것처럼 추가하지 않았다.

### P1 · 전환과 복귀의 완성 — 9/22 업데이트

- 기존 카드 확대/페이드는 제거했다. 메인·All Work·상세의 링크/버튼 이동은 브랜드 녹색 면이 아래에서 올라와 덮고(280ms), 첫 화면 미디어/폰트 준비 후 아래로 내려가는(360ms) 공통 전환을 사용한다. 대기 시간을 인위적으로 추가하지 않는다.
- 오버레이 상세에서 돌아오는 위치는 보존한다. 페이지 새로고침·브라우저 재시작·메인으로 완전히 나갔다가 새로 들어오는 상황까지 진행 위치를 영구 저장하지는 않는다.
- 실제 문서 이동도 head 진입 커버와 sessionStorage 표식으로 연결한다. 브라우저 기본 Back/Forward는 출발 애니메이션을 지연시킬 수 없으므로 복원 후 내려가는 reveal을 적용한다. 오버레이 내부 Back은 전체 cover/reveal을 적용한다. OS 뒤로가기 제스처 자체의 화면 효과는 브라우저가 소유한다.
- 느린/깨진 미디어의 무기한 커버를 방지한다(미디어 최대 2.2초, 폰트 최대 1.2초 대기, 상세 fetch 8초 타임아웃 및 일반 링크 fallback). 모션 감소 설정에서는 큰 이동 애니메이션을 생략한다.

### P1 · 실기기 검증

- 실제 iPhone/iPad Safari의 터치 관성, 버튼 탭, 주소 표시줄 높이 변화와 WebGL 성능.
- 마우스 실사용에서의 호버 해제 감각, 고해상도/저성능 기기의 렌더링, 스크린리더 전체 흐름.
- 테스트 브라우저는 화면 너비만 변경 가능하고 실제 coarse pointer 에뮬레이션을 제공하지 않는다. 따라서 터치 버튼의 위치·동작은 컨트롤러 테스트로 검증했고, 실기기 검증 완료로 표기하지 않는다.

### 선택 사항 · 이번 범위에서 추가하지 않은 것

- 빠르게 특정 작업을 찾는 별도 Index. 현재의 ‘작업만 보이는 공간’을 유지하려고 보조 목록이나 모드 전환을 새로 추가하지 않았다.

## 레퍼런스 적용 범위

[K95](https://k95.it/en)의 공개 호버 라벨 구조를 참고했다: 원형 pill, 반투명 배경, blur, 제목/분류, 커서 인접 위치, opacity/visibility 전환. K95의 글래스 스타일과 우리 녹색을 연결했으며 파란색·중앙 조형물·카드 휘어짐은 가져오지 않았다.

반경·카메라·이징 수치는 우리 카드 비율과 화면 밀도에 맞춘 설계값이다. K95와 동일한 카메라 구현이나 객관적인 ‘상위 1%’ 결과라고 주장하지 않는다. 이전 조사와 제안은 [리서치 문서](all-work-interaction-research.md)에 보존했다.

- 브라우저: 데스크톱 및 390px/768px 너비 화면, Pause, 상세 진입, 관련 섹션 제목 위치, 뒤로가기 버튼과 브라우저 Back 검증.

자동 테스트의 DOM은 모의 환경이다. 실제 GPU·터치 기기의 시각/조작 테스트를 대체하지 않는다.

## 9/22 · 경사 / 전경 크기 / 컨트롤

- 나선 상승 간격 계수 .40 → .44: 약 10% 증가. 회전 순서, 방향, 반경과 카메라는 유지.
- 데스크톱 peak scale 1.16 유지. 모바일/태블릿은 전경에만 최대 26% 확대를 가산한다. 화면 높이 및 좌우 여백에 따라 더 작게 제한하며 고정 CTA는 카드 아래로 함께 배치한다.
- 390×844의 정중앙 이미지 높이 약 299 → 377px. 768×1024 약 399 → 503px. 짧은 가로 화면은 확대보다 버튼/헤더와 겹치지 않는 것을 우선한다.
- Pause/Resume 앞에 Lucide pause/play 아이콘. [ISC 라이선스](https://lucide.dev/license), 저작권 및 허가문은 `assets/icons/lucide/LICENSE`에 보존.
- START/END 원을 카드와 동일한 GPU 깊이 버퍼에 그린다. 뒤에 있는 원이 앞 카드 위에 붙어 보이던 겹침을 수정. WebGL 불가 시 기존 DOM 원 유지.
- `node --test tests/space-transitions.test.cjs tests/work-rings.test.cjs`: 15개 테스트 통과. PC 크기 보존, 확대 상한, CTA 여백, 준비 후 reveal, 실패/모션 감소, 중복 클릭, history queue 및 문서 진입 표식 포함.
