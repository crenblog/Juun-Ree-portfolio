2026-09-21 · 시작 전 체크포인트: `415ca23`

상태: All work 방향 확정 및 1차 구현. 기존 roadmap의 All work 소개문·철학·Contact 섹션 제안은 아래 최신 요구로 대체한다.

## 2026-09-21 결정 — 3D work database

사용자 선택: K95처럼 작업 조각이 3D 공간에 떠 있고, 머릿속 데이터베이스에서 하나씩 꺼내 전달하는 인상을 만든다. 메인은 대표 작업 몇 개를 선별해서 보여 주고, All work는 탐색 공간으로 역할을 분리한다.

1차 구현:

- 기존 `js/gallery.js`의 곡면 투영·드래그·휠·키보드 탐색을 다시 연결했다.
- SeMA, Loop, Off를 각각 세 개의 기억 조각으로 펼쳐 총 9개 타일을 배치했다.
- 실제 제품 캡처가 아직 없는 조각은 포트폴리오용 추상 SVG 커버로 표시했다.
- 각 조각은 대응하는 SeMA, Loop, Off 상세로 연결한다.
- 소개 문단, 철학 카드, Contact 카드는 All work에 넣지 않았다.
- 다음 단계에서 실제 제품 캡처가 확보되면 SVG 커버를 교체한다.

## 확정된 요구

- `index.html`이 메인이다. 현재 사이드바, 크림 배경, 딥그린, 큰 산세리프, 얇은 구분선을 기반으로 개선한다.
- All work는 작업만 보여 준다. 별도 슬로건, 소개 문단, 작업 철학, 협업 권유 섹션을 넣지 않는다.
- 메인 상단에서 제품 이미지를 볼 수 있게 한다. 구체적인 배치는 비교 후 선택한다.
- 상세는 SeMA의 기존 내용과 위계를 출발점으로 삼는다.
- 레퍼런스의 정보 순서·이미지 비중·읽기 방식을 가깝게 참고한다. 문구·제품 화면·브랜드 자산은 Juun의 것으로 구성한다.
- 형식과 설명량을 먼저 비교하고 사용자 선택 뒤 구현한다.

## Juun에 적용할 제작 프로세스

아래는 위 자료에서 도출한 우리 프로젝트의 방법이며, ‘수상자 모두가 쓰는 비법’은 아니다.

1. 방문자 과업 정의: 메인에서 디자이너 이해 → All work에서 작업 선택 → 상세에서 기여와 판단 확인.
2. 자료 점검: 프로젝트별 실제 화면, 본인 역할, 제약, 결과 근거를 확인한다.
3. 같은 작업·같은 색·같은 설명량으로 레이아웃만 비교한다.
4. 한 케이스를 실제 콘텐츠로 먼저 구성하고 템플릿을 추출한다. 모든 케이스에 같은 길이를 강제하지 않는다.
5. 제목만 훑는 읽기, 이미지와 캡션을 보는 읽기, 본문을 읽는 경로를 각각 확인한다.
6. 데스크톱과 모바일에서 이미지 크기·문장 길이·클릭 경로를 검증한다.

필요한 역량: 콘텐츠 편집, 정보 구조, 이미지 아트디렉션, 반응형 그리드, 증거 검토, 접근성, 브라우저 구현 확인. 새로운 프레임워크 도입은 P0에 필요하지 않다.

## All work 비교안

모든 안에서 소개글은 없다. 공통으로 작업명과 연도를 최소 캡션으로 제안하되, 제목까지 숨길지는 사용자 선택 사항이다. 링크는 이미지와 제목 전체에 걸고, 터치에서도 발견 가능하게 한다.

| 안 | 구조 | 잘 보여 주는 것 | 비용/약점 | Juun 적용 |
| --- | --- | --- | --- | --- |
| A. 2열 갤러리 | 같은 크기의 이미지 2열 + 작은 제목 | 작업 간 비교, 전체적인 제품 감각 | UI 세부는 작음 | All work 추천. Jesse 구조 참고 |
| B. 큰 이미지 연속 | 넓은 이미지 1열 + 작은 제목 | 각 제품의 화면과 분위기 | 작업 수가 늘면 길어짐 | Cameron 구조 참고. 큰 커버 확보 시 유리 |
| C. 이미지가 보이는 인덱스 | 작은 이미지 + 이름 + 연도의 행 | 빠른 탐색, 기존 사이트와의 연속성 | 첫인상에서 제품 크기가 작음 | 현재 메인 목록을 가장 적게 바꾸는 안 |
| D. 자유 배치/드래그 | 공간에 작업을 놓고 이동 | 탐색의 재미 | 위치 기억·모바일·키보드 구현 부담 | 기존 gallery 코드가 있으나 기본 탐색으로는 후순위 |

D는 기존 코드 기반 선택지이며 이번에 직접 검토한 수상 사이트에서 공통으로 발견한 패턴은 아니다. A–C는 `p0-layout-options.html`에 동일한 콘텐츠로 시각화했다. 색 면은 미디어 자리 표시이며 실제 작업 화면이 아니다.

추천 조합: **메인 상단에 대표 제품 이미지 + 기존 목록 유지·보강 / All work는 A / 상세는 아래 2번**. 메인과 All work의 역할이 겹치지 않으며 기존 인덱스 개성을 남긴다. 아직 확정하지 않는다.

## 상세 표현 방식 비교

1. 갤러리 중심: 큰 결과 화면 → 짧은 설명 → 다음 화면. 시각적 결과가 강한 짧은 작업에 적합. 판단 근거가 부족해질 수 있다.
2. 결정 중심 에디토리얼: 요약·이미지 → 문제 → 핵심 결정 2~3개와 해당 화면 → 검증. SeMA 추천. 기존 선택지 비교를 활용한다.
3. 과정 중심 보고서: 리서치 → 인사이트 → 탐색 → 솔루션 → 검증. 조사 깊이가 핵심일 때 유리하지만 제품을 만나는 시점이 늦다.

### 공통 콘텐츠 계약 초안

필수: 제목 / 한 문장 문제 / 실제 대표 화면 / 본인 역할과 팀 / 기간 / 프로젝트 상태 / 핵심 결정 / 결과와 근거 / 다음 작업.

선택: 사용자 인용, 대안 비교, 실제 테스트 기록, 화면 전후 비교, 프로토타입 링크, 구현 제약. 자료가 없으면 섹션을 생략하고 사실을 만들어 채우지 않는다.

SeMA 기본 흐름 제안:

```text
제목 + 컨셉 여부 + 역할
대표 제품 화면 + 한 문장 개요
문제: 입구에서 무엇을 볼지 고르기 어려움
결정 1: 브라우저 진입 / QR 흐름 + 이유
결정 2: 시간으로 선택 / 실제 화면 + 대안
결정 3: 다음 작품 안내 / 실제 흐름 + 제약
검증: 방법·표본·수치·한계
배운 점 / 다음 작업
```

본문 폭은 약 60~70자 읽기 폭, 이미지는 넓게 쓴다. 이는 초기 설계값이며 실제 한·영·일 문장과 화면으로 조정한다. ‘Research’ 같은 방법명만으로 장을 나누기보다 해당 장이 답하는 질문이나 결정을 제목으로 쓴다.

## 프로젝트 인벤토리 — 공개 준비와 근거 확인

| 작업 | 현재 판단 | 필요한 자료 |
| --- | --- | --- |
| SeMA | 대표 케이스 후보. 현재 본문은 concept라고 명시 | 실제 UI, 테스트 원자료와 n=10 및 수치 확인, 기관과의 관계 |
