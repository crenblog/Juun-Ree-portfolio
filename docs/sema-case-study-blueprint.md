# SeMA 상세 — 리서치와 개편 설계안

2026-09-22 · 조사/설계 단계 · 실제 사이트 변경 전

## 0. 이번 작업의 전제

사용자 확인: 현재 SeMA의 인터뷰, 테스트, 성과 수치는 실제 기록이 아니라 예시다. 지금 목표는 실제 자료 투입 전, 재사용 가능한 상세의 구조·표현·읽기 경험을 완성하는 것이다.

- 자료가 없다는 이유로 구조 설계를 멈추지 않는다.
- 시안의 설명·화면·데이터에는 예시임을 표시한다. 실제 리서치나 성과를 새로 지어내지 않는다.
- ‘상위 1%’를 객관적 순위로 주장하지 않는다. 수상작의 시각적 완성도, 실제 프로덕트 디자이너의 설명 방식, 채용 관점의 평가 기준을 따로 검토한다.
- 이번 산출물은 이 개편안과 별도 시안이다. `biennale.html`, 공통 스타일, 번역 데이터의 실제 개편은 아직 적용하지 않는다.

## 1. 결론

**추천: 이미지로 시작하고, 핵심 설계 판단 세 가지를 증거와 함께 읽는 에디토리얼 케이스 스터디.**

전달해야 할 것은 ‘프로세스를 많이 수행했다’가 아니라 다음 다섯 가지다.

1. 누구의 어떤 상황을 바꾸려 했는가.
2. 내가 책임진 범위는 어디까지인가.
3. 어떤 근거로 방향을 선택하거나 바꿨는가.
4. 그 판단이 실제 화면·상태·행동에 어떻게 반영되는가.
5. 무엇을 확인했고 무엇은 아직 모르는가.

All Work는 발견하는 공간, 상세는 고른 생각을 차분히 펼쳐 읽는 공간으로 구분한다. 상세 안까지 원통 이동이나 스크롤 연출을 이어가지는 않는다.

## 3. 현재 SeMA에서 먼저 바꿀 것

### A. 결과를 보기 전에 선언문을 너무 오래 읽는다

현재 첫 화면은 프로젝트명, 긴 앱 이용률 문장, 숫자 세 개, 작은 메타데이터다. 이어지는 큰 `SeMA` 글자는 제품을 설명하지 않는다. 실제 제품 UI는 Context → Problem → Research → The fork 뒤에 나온다.

**개편:** 첫 화면에 제목·설명 한 문장·프로젝트 상태를 보여주고 대표 화면이 바로 시작되게 한다. 수치는 제품을 이해한 다음 읽으며, 예시 단계에서는 성과처럼 강조하지 않는다. 대형 SeMA 단독 마크 영역은 대표 화면으로 대체한다.

### B. 여백이 있는데도 구분은 약하다

현재 SeMA의 장은 모두 `padding:88px 0`과 상단 선이다. 작은 장 제목은 11px 대문자이고, 질문형 문장은 28–40px다. 같은 강도의 제목·줄·여백이 반복되어 읽기 리듬이 단조롭다.

**개편:** 장 경계는 크게, 같은 주장과 그 근거는 가깝게. 전부 카드로 감싸거나 전부 가로줄로 나누지 않는다. 본문·비교·큰 화면·결과 요약을 서로 다른 역할로 사용한다.

### C. 글이 행동보다 수사적인 표현에 기댄다

예: ‘URL이 제품입니다’, ‘지도가 장소를 가르칩니다’, ‘제품이 없는 것과 같습니다’. 브랜드 문장 하나로는 쓸 수 있지만 계속 반복되면 판단 과정을 확인하기 어렵다.

**개편:** ‘무엇을 바꿨다 → 어떤 근거가 있었다 → 무엇을 포기했다 → 화면에서 어떻게 보인다’로 쓴다. 선언형 문장은 해당 장의 결론 하나만 남긴다.

### D. 현재 비교안의 분류가 겹친다

Native app / Browser guide / Paper map + QR은 같은 축의 대안이 아니다. QR은 브라우저 가이드의 진입 채널이기도 하다. 종이 지도를 ‘제품 아님’으로 단정하면 검토의 공정성도 떨어진다.

**개편:** 플랫폼 결정(네이티브/웹)과 진입·백업 결정(QR 안내/종이 지도)을 분리한다. 채택안의 장점만 나열하지 않고 오프라인·위치 정확도·운영 비용 같은 손실도 기록한다. 예시라도 논리적으로 성립해야 한다.

### E. 기능 설명과 이미지의 역할이 맞지 않는다

현재 QR 온보딩 블록에는 `assets/images/at/*.jpg` 인물 사진 슬라이더가 있다. 이 모듈은 QR을 어디에서 만나고 어디로 이동하는지 보여주지 못한다. 앞의 폰 두 개도 설명용 UI이고 실제 프로토타입이 아니다.

**개편:** 해당 모듈을 ‘입구 안내 → QR 열기 → 첫 선택’의 동일 맥락 화면으로 교체할 수 있는 슬롯으로 설계한다. 지금은 분명하게 표시된 예시 UI를 넣는다. 장식 사진으로 빈 증거를 메우지 않는다.

### F. 테스트 결과와 제품 특성이 같은 KPI처럼 보인다

`3/10 → 9/10`, `6분 → 40초`는 테스트 형식이고 `설치 0`은 제품 특성이다. 같은 세 칸에 넣으면 결과와 설계 의도가 섞인다.

**개편:** ‘검증 결과’와 ‘제품의 주요 선택’을 구분한다. 결과 데이터가 없을 때도 레이아웃이 성립하도록 결과 모듈을 선택형으로 만든다. 연구를 하지 않았다면 ‘검증 계획’을 넣고 통과한 것처럼 쓰지 않는다.

## 4. 구조 후보와 추천

| 형식 | 장점 | SeMA에 대한 판단 |

| B. 비주얼 쇼케이스 | 이미지가 아주 좋으면 즉시 인상적이다. | 실제 화면이 충분해진 뒤 보완 가능. 지금은 과정이 빈약해 보일 위험. |
| C. 모든 프로세스를 시간순으로 기록 | 누락 없이 자료를 보관하기 좋다. | 본문이 아니라 부록에 적합. 결과를 보기까지 너무 오래 걸린다. |

‘전부 들어간다’는 것은 모든 과정을 같은 크기로 드러낸다는 뜻이 아니다. 핵심은 항상 보이고, 세부 방법·원자료는 필요할 때 펼친다.

## 5. 추천 페이지 순서 — 하나의 이야기, 세 단계의 읽기 깊이

아래 시간은 방문자 행동에 대한 통계가 아니라 시안 검토용 목표다.

- **약 20초 훑기:** 이름, 사용자 가치, 대표 화면, 역할/상태, 핵심 결정.
- **약 2분 이해:** 각 장의 결론, 주요 화면, 비교안, 결과/한계.
- **깊게 읽기:** 자료 캡션, 상세 방법, 상태 정의, 테스트 메모.

| 순서 | 독자가 묻는 질문 | 내용 슬롯 | 권장 레이아웃 |
| --- | --- | --- | --- |
| 01. 시작 | 무엇을 만든 것인가? | 프로젝트명, 한 문장 가치, 콘셉트/출시 상태 | 짧은 제목 + 큰 제품 화면. 이미지부터 시작하는 대안도 비교 가능. |
| 02. 한눈에 | 무엇을 담당했고 핵심이 무엇인가? | 역할·협업·기간·범위, 핵심 선택 3줄 | 얇은 메타 줄 + 짧은 요약. 수치가 없으면 KPI 칸을 만들지 않음. |
| 03. 문제 | 누구의 어떤 순간이 어려운가? | 특정 시나리오, 기존 흐름, 사용자/조직 제약 | 좁은 읽기 폭 + 기존 흐름 그림 하나. |
| 04. 근거 | 왜 그 문제가 중요하다고 봤는가? | 관찰/자료 → 해석 → 결정 연결 2–3개 | 원자료 일부 + 캡션. 방법 상세만 접기. |
| 05. 판단 | 어떤 대안 중 왜 이것을 골랐는가? | 플랫폼·정보 우선순위·진입 방식의 판단 | 공통 기준으로 비교. 선택안/손실/남은 위험 표시. |
| 06. 제품 | 사용자는 실제로 무엇을 하는가? | QR 진입 → 시간 선택 → 다음 작품, 각 장면의 상태 | 3개의 설명+화면 모듈. 장식 숫자 140px 열 대신 이미지에 폭 할당. |
| 07. 검증 | 확인된 것과 아직 모르는 것은? | 방법, 참가자/조건, 결과, 수정사항, 한계 | 결과 표 또는 전후 비교. 데이터 없으면 검증 계획으로 대체. |
| 08. 마무리 | 이 경험이 다음 판단을 어떻게 바꾸는가? | 배운 점 1개, 다음 실험 1개, 다음 작업/원래 공간으로 | 짧은 회고 + 명확한 복귀. 긴 자기평가 문단 제외. |

## 6. 재사용할 핵심 모듈: ‘설계 판단’

각 모듈은 아래 순서만 공통으로 쓴다. SeMA의 사실을 끼워 맞추는 템플릿이 아니라 자료를 담는 그릇이다.

1. **결론 제목:** 무엇을 바꿨는지 한 문장.
2. **이유:** 2–3문장. 관찰과 해석을 구분.
3. **증거:** 화면/노트/실험 결과 중 하나. 자료가 없으면 가설로 표시.
4. **제품 반영:** 변경 후 화면과 1–3개 주석.
5. **대가와 다음 확인:** 한 줄.

예시 제목:

- ‘설치보다 첫 관람을 먼저 시작하게 한다.’
- ‘작품 목록보다 남은 시간을 먼저 묻는다.’
- ‘현재 위치에서 다음 행동까지 이어준다.’

세 제목은 현재 프로젝트 콘셉트를 설명하기 위한 **예시**다. 실제 연구로 확인되었다는 뜻이 아니다.

### 예시 문장 교체

기존: ‘시간이 내비게이션입니다. 완전함은 버렸습니다.’

시안: ‘첫 선택을 작품 목록에서 관람 시간으로 바꿨다. 제한된 시간 안에 볼 수 있는 경로를 먼저 제안하는 방식이다. 대신 자유롭게 탐색하려는 관람객을 위해 전체 목록으로 가는 경로를 남긴다.’

실제 데이터 투입 시 덧붙일 것: 결정의 근거, 대안과 비교한 조건, 사용자가 이해하지 못한 부분, 수정 화면. 의도가 성공했다는 서술은 검증 뒤에 쓴다.

## 7. 시각 디자인 기준

다음 수치는 레퍼런스에서 복제·측정한 정답이 아니라 우리 스타일에 맞춘 시작값이다.

| 본문 읽기 폭 | 600–680px | 가용 폭 전체 |

- 아이보리 `#F1EDE8` 기본. 숲색 `#0C3024`는 제목·링크·선택 상태에 제한적으로 사용. 넓은 세이지 면은 대표 미디어에만 우선 사용.
- 포트폴리오의 폰트 체계를 유지한다. 장식용 폰트를 추가하지 않는다. EN/KR/JP의 실제 줄바꿈은 각각 확인한다.
- 모든 단락을 중앙 정렬하지 않는다. 본문은 왼쪽 정렬, 영어 55–75자 안팎/한글 30–40자 안팎을 초기 가이드로 실제 화면에서 조정한다. 이는 접근성 인증 기준이 아니다.
- 대문자 11px만으로 장 이름을 읽게 하지 않는다. 의미 있는 H2를 노출한다.
- 기본 필수 정보의 대비를 낮추지 않는다. 사진/캡처의 텍스트가 작으면 크롭 확대 또는 원본 보기로 해결한다.
- 장 제목 아래, 미디어 위에 여백을 더하는 것으로 시선 순서를 만든다. 빈 화면 한 장은 여유가 아니라 정보 지연이 될 수 있다.
- [W3C Text Spacing](https://www.w3.org/WAI/WCAG21/Understanding/text-spacing.html)은 사용자가 간격을 늘렸을 때 내용이 잘리지 않아야 한다는 기준이다. 기본 행간 1.5를 강제하는 규칙으로 오해하지 않는다.

## 8. 조작과 모션

- 상세 안의 스크롤은 일반적인 세로 스크롤. 섹션 스냅, 문장 등장 대기, 자동 넘김 없음.
- 대표 영상은 짧고 목적이 명확할 때만. 기본 포스터와 재생/정지, 모션 감소 대응. 중요한 설명을 영상에서만 제공하지 않는다.
- 목차는 `Overview / Decisions / Experience / Validation` 정도의 짧은 구조로 시작. PC는 여유 폭이 있을 때 작은 측면/상단 위치, 모바일은 ‘목차’ 버튼으로 노출. 기존 읽기 슬라이더와 두 개의 강한 탐색 장치를 동시에 만들지 않는다.
- 기존 All Work의 related fragment 링크는 관련 장으로 이동하고, 상세를 닫으면 원래 탐색 위치로 복귀한다.
- 원자료 확대는 클릭/탭과 키보드로 동일하게 동작. 닫기와 원래 포커스 복귀가 필요하다.
- 접기는 세부 연구 방법·보조 자료에만 사용. 문제, 개인 역할, 핵심 결정, 결과/한계는 기본 상태에서 보인다.

## 9. 실제 데이터 투입을 위한 콘텐츠 모델

각 섹션에 `id`, `title`, `summary`, `body`, `media[]`, `evidence[]`, `status`를 둔다. 각 미디어에는 `kind`, `src`, `alt`, `caption`, `source`, `aspectRatio`를 둔다. 결과에는 `metric`, `before`, `after`, `unit`, `sample`, `method`, `period`, `limitations`를 따로 둔다.

상태는 `example / hypothesis / verified`로 구분한다. 시안에서는 example을 표시한다. 공개용 실제 포트폴리오에서 예시가 실적으로 보이지 않도록 빌드 또는 콘텐츠 검수 단계에서 확인한다.

- 자료가 없어도 가짜 결과로 빈 칸을 채우지 않는다. 결과 → 검증 계획 모듈로 바꿀 수 있어야 한다.
- 1장/3장/영상의 모든 미디어를 같은 고정 높이로 강제하지 않는다.
- 같은 케이스를 index/work/standalone에 별도 복사해 관리하지 않고 canonical case body를 기준으로 정리한다.
- 기존 `bH4`, `csH5` 같은 번역 키와 fragment 연결을 깨뜨리지 않도록 콘텐츠 ID와 번역 키를 분리하고 이전 링크 매핑을 보존한다.
- ‘입장권/매표소’, 전시실 이름, 작품/거리, 40·90·180분 같은 세부 내용도 현재는 예시이므로 교체 가능한 필드로 둔다.

## 10. 진행 순서와 완료 기준

### P0-1 · 구조와 한 모듈부터

첫 화면, 요약, 설계 판단 1개, 결과/검증 계획의 구조를 시안으로 비교한다. 제목 우선/이미지 우선 두 안을 보되, 내용의 순서는 동일하게 둔다.

완료 기준: 제목과 대표 화면만 보고 무엇을 위한 제품인지 설명할 수 있다. 장 제목만 읽어도 문제→판단→제품→검증의 연결이 이해된다.

### P0-2 · 예시 데이터로 전체 템플릿 구현

세 개의 제품 장면, 대안 비교, 보조 자료 접기, 복귀/목차를 연결한다. 의미 없는 SeMA 마크·QR 블록의 인물 슬라이더는 새 미디어 슬롯으로 교체한다. 실제 자료는 기다리지 않는다.

완료 기준: 모바일에서도 읽는 순서가 같고, 필수 정보가 접힌 상태에 숨지 않으며, 모든 예시가 예시로 식별된다.

### P1 · 내용 길이/미디어 스트레스 테스트

짧은 제목/긴 제목, 한글/영문/일문, 이미지 없음/1장/여러 장, 결과 없음/결과 있음, 320px부터 넓은 PC까지 검사한다. 텍스트 확대와 간격 재정의, 모션 감소, 키보드 탐색도 확인한다.

완료 기준: 고정 높이 때문에 문장이 잘리지 않는다. 이미지가 없다고 큰 빈 상자가 남지 않는다. 모든 화면의 캡션과 호출 관계가 맞는다.

### P2 · 실제 자료 교체 및 공개 검수

검증된 자료와 역할·조건을 넣고 수치의 정의, 기간, 한계를 검수한다. 운영 전환·성과 과장·근거 없는 인용을 제거한다. 이 단계가 예시를 실적으로 바꾸는 유일한 시점이다.

## 11. 이번 결정과 아직 결정하지 않은 것

결정: 에디토리얼 기반, 대표 화면 조기 노출, 결정 중심의 본문, 아이보리 유지, 보조 자료만 접기, 예시 데이터로 구조 작업 계속.

미결정: 최종 대표 미디어, 실제 세 가지 핵심 결정, 최종 목차 위치, 이미지 원본 보기 방식. 실제 콘텐츠 없이는 확정할 수 없는 부분은 슬롯으로 남기되 디자인 진행을 막지 않는다.

별도 시안은 구조·정보량·여백을 비교하기 위한 것이다. 실제 연구/결과를 나타내지 않으며 실제 페이지에 적용된 결과도 아니다.
