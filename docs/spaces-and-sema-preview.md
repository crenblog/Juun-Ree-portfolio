# Spaces + SeMA HTML 테스트 · 2026-09-22

## 이번 결과

- `sema-preview.html`: 원본 SeMA를 보존한 실제 HTML 테스트 페이지. 기존 SeMA 첫머리의 ‘새 상세 HTML 시안 보기’로도 진입할 수 있다.
- 큰 제목 → 대표 제품 UI → 문제의 순간 → 판단 세 가지 → 진입/시간 선택/경로 화면 → 검증 계획. 설명 자료와 인터랙션은 시안이며 실제 연구·성과 수치는 넣지 않았다.
- 긴 본문은 읽기 폭을 제한하고, 제품 화면과 참고 사진은 넓게 배치했다. 상세 방법만 접을 수 있다. 시간 선택 40/90/180은 실제 버튼이며 설명 상태를 바꾼다.
- 참고 사진은 기존 라이선스 확인 에셋을 재사용했다. 실제 SeMA 현장 사진이 아니라는 설명을 함께 표시한다. 화면·도식·안내물은 코드 기반 예시다.

## 공간 이동

- 메인 → All Work: 현재 화면이 왼쪽, 새 화면이 오른쪽에서 이동한다. 복귀는 반대. 기존 메인의 두 열 너비는 바꾸지 않는다.
- 지원 브라우저에서는 Cross-document View Transitions로 이전/다음 화면을 동시에 움직인다. 540ms, `cubic-bezier(.22,.72,.18,1)`. 수치는 우리 사이트용 설계값이지 자연계나 특정 수상작에서 검증된 값이 아니다.
- 상세는 기존 위에 겹쳐 열리는 흐름을 유지한다. 전환 면은 녹색 대신 기본 아이보리 `#F1EDE8`.
- WebGL 화면이 문서 전환 중 비는 WebKit 현상을 피하도록 출발 순간의 그림만 보존하고 복귀 후 해제한다. 새 공간은 렌더 블로킹 모듈에서 이미지/폰트를 준비한다(최대 1.8초). 인터랙션을 대신하는 정적 화면이 아니다.
- 지원하지 않는 브라우저는 방향에 맞는 아이보리 면 전환으로 폴백한다. 모션 감소 설정에서는 큰 이동을 생략한다.
- 참고한 공식 문서: [WebKit cross-document transitions](https://webkit.org/blog/16967/two-lines-of-cross-document-view-transitions-code-you-can-use-on-every-website-today/), [Chrome lifecycle](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document).

## All Work 반응형

| 구간 | 앞 카드의 기준 높이 | 원통 반경 |
| --- | --- | --- |
| 600px 미만 | 380px | 3.6 |
| 600–1079px | 480px | 4.45 |
| 1080px 이상 | 기존 PC 화면 높이 비율 유지 | 5.95 (기존 6.4) |

폭을 조금 바꿀 때마다 크기가 변하는 것이 아니라, 같은 구간에서는 같은 기준값을 유지한다. 실제 높이는 헤더·하단 버튼과 좌우 안전 여백이 부족할 때만 줄어든다. 기기 방향에 따라 카메라가 교체되는 기존 분기는 제거했다.

`Scroll to explore`는 제거. 자동 흐름은 `Auto scroll · On / Off`와 일시정지/재생 아이콘으로 표시한다. 수동 스크롤은 자동 흐름을 꺼도 계속 작동한다. 사용자 조작마다 강제 정지시키지 않는다.

## 검증 범위

컨트롤러/전환 상태 자동 테스트, 브라우저 실제 양방향 이동, SeMA 시간 선택, 모바일 가로 넘침과 이미지 로드, PC/모바일/태블릿 레이아웃을 확인한다. 실기기 터치 성능·VoiceOver 전체 사용 흐름·모든 브라우저의 폴백 시각 검증까지 완료했다는 의미는 아니다.
